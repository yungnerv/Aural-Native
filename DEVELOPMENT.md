# Development

Models contain portable track data. Library owns versioned persistence, indexing, streaming content hashes and importing. Playback separates AVPlayer/session ownership, queue ordering, progress and main-actor coordination. System owns Now Playing and remote command registration. Artwork owns bounded asynchronous decoding. Views own presentation; playback progress is observed only by a small subtree. Scripts contain CI tests and IPA packaging.

## Storage contract

The AuralLibrary directory and existing media filenames remain unchanged. Legacy arrays and schema 1 envelopes are accepted; a successful mutation writes schema 2. Opening old libraries does not rewrite them. The previous valid index is preserved as library.previous.json. Unreadable or unsupported indexes, including missing indexes alongside existing media, block mutations. The repository refuses to delete any file still referenced by the committed index. Recovery is deliberate; the backup is metadata only, not a copy of music. Media deleted from the current index remains available to the previous index until a subsequent successful index rotation; older pre-0.3.0 backups may still lack media. Unknown files are never automatically removed; an interrupted import may leave orphan files. Do not downgrade after migration to a version that cannot read the current schema. Keep original audio separately.

Favorite changes use an atomic sidecar bound to the SHA-256 of the current index. The next structural commit folds them into both snapshots before retiring the sidecar. Older app builds cannot display pending changes. An unreadable sidecar or concurrent write blocks mutation.

Imports are serialized with other mutations, lazily hash legacy tracks, stream new hashes in bounded chunks and commit in adaptive batches of 16–128. Index commit precedes deletion. Imports use uniquely owned staging directories and separate artwork filenames. Cleanup targets only owned uncommitted files or files referenced by a retired valid backup and neither current nor previous index. A cleanup failure is diagnostic, never a failed committed transaction. Atomic JSON is retained until large-library measurements justify a tested SQLite migration.

## Build and release

iOS/iPadOS 26.1+. CI validates iPhone and iPad on independent clean runners before running the model and device packaging gates. VERSION is the sole release version. project.yml contains only a placeholder; Scripts/build.sh supplies the real version and build number for both CI and local builds. The bundle keys expand from build settings and exact values are logged and checked. Automatic CI runs for pull requests and relevant main changes. Optional manual prereleases publish unsigned IPA and checksum. Keep main buildable. Do not merge until CI succeeds; do not call device behavior validated until tested.

## Remaining validation

Physical-device signing, interruptions and background playback, storage recovery tooling, profiling at large-library scale, extended decoders, gapless playback and full PWA parity remain outstanding. Playback engine and system controller have independent ownership and observation lifetimes. Physical-device lifecycle testing remains required.

Packaging is implemented in Scripts/package.py. CI parses both shell scripts and exercises packaging against synthetic bundles before invoking Xcode. The packager validates bundle identity, version, executable and archive integrity, preserves executable permissions, rejects escaping symlinks, and publishes checksum and build metadata only after archive validation. Synthetic fixtures do not establish actual iOS installation compatibility.

A genuinely new, empty library receives a current-schema index before importing. Interrupted first imports therefore cannot make the library appear to have lost its index. Before any commit or media deletion, the repository compares the on-disk index with its last known bytes and fails closed if they differ. This is a single-process, single-writer architecture with accidental stale-writer detection, not a multiprocess locking guarantee.

## Recovery and audit corrections (0.2.1)
The empty index is written atomically before import. A corrupt or missing index can be inspected and explicitly restored from the previous snapshot only when all referenced audio and artwork files are regular files and present. A healthy index or unsupported newer schema is not eligible. Preserve damaged bytes in a uniquely named archive; do not delete media or unreferenced files during recovery. Missing media blocks restore. Explicit restore verifies stored SHA-256 hashes where present; legacy audio without a recorded hash is checked for regular-file presence only. The UI exposes an explicit retry and confirmation; stale writes and direct stale deletions both invalidate the repository. Recovery is not a replacement for external music backups. A 10,000-track synthetic metadata fixture checks host serialization and index behavior, not device performance or actual 10,000-file import.

## Simulator and toolchain gates
CI now validates an exact Xcode version (26.6), the reviewed XcodeGen version (2.46.0) and immutable GitHub Action commits. XcodeGen is obtained from its exact official GitHub release archive, verified against a pinned SHA-256 digest, and kept alongside its original setting presets. Homebrew is not used. Xcode must match build 17F113; unexpected tool versions fail closed. This is tool-version control, not a bit-for-bit reproducibility guarantee. Simulator tests exercise import bytes, duplicate rejection, failed import cleanup, playback intent/lifecycle and fresh launch. Swift 6 language mode and warnings-as-errors are required for the app, native tests and portable Swift suite. Remote commands reject unavailable requests and stale queued track IDs; an accepted command is not a guarantee of successful audio rendering. Native integration and UI tests must pass before publication.

## Swift 6 observer ownership
Playback and remote-command observer tokens are owned by the main actor, including isolated destruction. Item notifications are registered for a specific item; queued callbacks carry value-type generation identifiers instead of transferring Notification or player-item objects. Replacing an item or player invalidates previously queued work, including seeks. Remote handlers are explicitly Sendable and the small cross-thread state uses the standard-library Mutex. Integration tests exercise stale notifications and observer release. Swift warnings fail compilation; unrelated Xcode tool diagnostics are still reviewed separately. Physical device audio-session and performance validation remain mandatory.

Interrupted imports may leave owned staging directories or unreferenced published files; no automatic deletion of unknown or ambiguous files. A later explicit reconciliation workflow remains necessary. A previous-index backup is not a substitute for external backups; after deletion its files may be reclaimed only when that snapshot is retired by a successful commit.

Playback revisions distinguish repeated preparations of the same track. Remote commands and scrubbing are bound to the revision; unavailable libraries block new playback, seeking and queue traversal, but allow pausing an already playing item. The session is released on pause/clear, and failed items are re-prepared on explicit resume. Device audio-session behavior, same-item seek/end interaction and VoiceOver adjustments still require native validation.

Library index snapshots are the single published source of track metadata. Search runs on cancellable immutable snapshots outside the main actor, and UI results must match the current revision, category and query. Adaptive import batches reduce repeated full JSON writes but do not change the algorithm to linear scaling; real import and device profiling remain necessary. A crash can leave up to one batch unindexed.

Import cancellation preserves successfully committed batches and rolls back owned pending media. Progress publications are throttled; full import diagnostics are available in Settings for the current session. Host tests use the pinned Xcode version. The iPhone simulator runs integration and launch tests; iPad separately runs the launch suite. Timing measurements are informational until repeated on representative hardware.

## Metadata evolution (0.3.1)
Schema 2 adds optional TrackMetadata with typed disc/track positions, album artist, composer, genre, release and recording date tags kept separately, and original filename. No music is rewritten. Older tracks remain valid with absent extended metadata; existing files are not automatically rescanned or reimported. ID3/iTunes mappings use AVFoundation's documented identifiers and support text positions and recognized binary iTunes position payloads; other tag formats, unusual encodings, numerical genre tables and broader codec support need fixture-based validation. Album grouping uses explicit album artist when present and otherwise track artist; unknown albums remain singles. Disc/track ordering preserves original order for ties and unnumbered tracks. Release disambiguation, tag editing, playlists, lyrics and library export will build on these stable track identities when implemented, rather than shipping unused speculative infrastructure. Newer schema backups are protected against overwrite.

Native Liquid Glass is a persistent presentation requirement, independent of library and playback state. The current UI is not yet a complete Liquid Glass implementation.

A generated tagged M4A fixture validates actual embedded metadata extraction and exact import bytes without shipping copyrighted media. The device build checks ARM64 and Mach-O iOS platform before packaging; simulator binaries are not accepted as device IPAs. Tests do not establish signed installation compatibility.


## Current presentation

Albums, Artists, Songs, Favorites and Settings use the system tab bar. Each browser keeps its own navigation stack. A single glass mini-player in the selected tab’s bottom safe area provides separate accessible playback and transport buttons. iPad uses native top navigation in regular width. The full player adapts to the available sheet width and Dynamic Type.

## Verified recovery and reclamation (0.3.6)
Recovery preview and restore share the same per-candidate inspection: regular-file check, cancellation-aware streaming SHA-256 for media with recorded hashes, count missing/damaged/unverified files separately. Legacy media without a checksum remains recoverable by explicit confirmation, but is not presented as verified. New artwork is checksummed at import; optional field is backward readable without a schema bump. Retired backup cleanup requires app-generated UUID naming and matching digest for each individual file; these are conservative ownership checks, not a cryptographic authorization ledger. Unverified legacy and modified media remain on disk with diagnostics. This deliberately favors data preservation over aggressive cleanup; explicit orphan reconciliation and a durable ownership record remain future work. No physical-device or performance claims before testing.

## Build #22 failure investigation (0.3.7)
The failing fixture rotated the guarded backup by committing `hashed`, copied from `first`. `legacyArt` was also copied from `first`; both had the same UUID-derived audio and artwork names. The repository correctly excludes names referenced by the new index, so two of the expected four diagnostics could not occur. Replace the new snapshot with an independent track, assert all four exact diagnostics, preserve existing byte checks, and independently exercise the original reintroduction case with valid matching checksums. Production cleanup is unchanged; the tests are stricter and cover both conditions. CI is required to confirm the fix.
